# 股票交易全流程分析

对 `$ARGUMENTS` 执行一轮分阶段、证据驱动的股票交易研究。目标是把技术、基本面、事件、资金、多空观点与风险约束连接成可执行但不代客交易的研究方案。

## 0. 建立研究合同

先写明：

- 证券名称、代码、交易所/市场；
- 数据截止日和实际最后交易日；
- 币种、复权口径、报告语言；
- 默认研究周期（未指定时采用 1–3 个月交易观察 + 6–12 个月研究目标）；
- 3–6 个可证伪问题；
- 数据源优先级、已知缺口和非个性化仓位声明。

结构化金融数据使用团队绑定的同花顺 `ifind-finance-data` Skill，以及工具箱已配置时自动启用的 `juyuan` MCP；按字段覆盖选择来源并交叉核验关键指标，关键事实再以交易所、公司公告和监管披露复核。

若证券代码或市场有歧义，先提出一个最小澄清问题。不要就风险偏好反复追问；最终仓位以“模型组合风险预算上限”表达。

## 1. 初始化唯一进度计划

调用一次 `update_task_progress`，按以下 8 个稳定阶段 ID 创建步骤。工具每次最多接受 8 项，不得展开成 14 个成员步骤：

1. `phase-1-research`：四维研究并行；
2. `bull-researcher`：多头论证；
3. `bear-researcher`：空头反证；
4. `research-manager`：多空裁决；
5. `trader`：交易提案；
6. `risk-panel`：三方风险评估并行；
7. `risk-manager`：风险调整后最终裁决；
8. `report-audit`：首席策略官汇总、审校与三格式交付。

开始时仅把 `phase-1-research` 设为 `running`，其余为 `pending`。四位第一阶段分析师和三位风险分析师的个人状态由团队成员事件展示，不要重复塞入进度计划。

## 2. Phase 1：四维分析并行

在同一轮调用中 `spawn` 四位成员，标签必须精确为：

- `market-analyst`
- `fundamentals-analyst`
- `news-analyst`
- `sentiment-analyst`

每份任务必须包含完整研究合同、截止日、数据源优先级以及角色专属要求。要求成员返回：

- 明确结论和 0–10 评分；
- 关键数据表、来源标题/URL、数据日期与口径；
- 反证、缺口和置信度；
- 角色 Playbook 指定的结尾标记。

不得在四位成员返回前进入下一阶段。收到结果后解决明显的标的、日期、单位和口径冲突；无法解决的冲突保留并降级置信度。

## 3. Phase 2：多空辩论与研究主管裁决

### 3.1 多头研究员

把四份 Phase 1 完整报告或无损证据矩阵放入任务，`spawn(label: "bull-researcher")`。多头必须给出 3–5 条有数据支撑的核心逻辑、催化剂、情景目标、失效条件和信心评分。

### 3.2 空头研究员

多头完成后，把 Phase 1 证据和多头完整论证放入任务，`spawn(label: "bear-researcher")`。空头必须逐项反驳多头、给出 3–5 条下行逻辑、下行情景、潜在跌幅和信心评分。

### 3.3 研究主管

多头和空头完成后，把双方论证与 Phase 1 证据放入任务，`spawn(label: "research-manager")`。研究主管必须：

- 区分已验证事实、计算、预测和观点；
- 给多头、空头各论点 1–10 权重；
- 明确输出 `BUY`、`SELL` 或 `HOLD`；
- 给出 12 个月目标区间、估值/情景方法、信心水平和改变判断的变量。

不得用简单投票或平均分替代证据质量判断。

## 4. Phase 3：交易员方案

研究主管完成后，将投资计划、关键行情、支撑阻力和事件窗口放入任务，`spawn(label: "trader")`。交易员必须给出：

- `FINAL TRANSACTION PROPOSAL: BUY/SELL/HOLD`；
- 分批入场或观察区间；
- T1/T2/T3 目标；
- 价格止损和基本面止损；
- 模型组合仓位上限；
- 时间节奏和每一目标的收益风险比计算。

价格精度应符合证券最小报价单位，不要无意义地伪精确。

## 5. Phase 4：三方风险辩论并行

把研究主管计划、交易员方案和最重要的正反证据放入三份自包含任务。在同一轮调用中并行：

- `aggressive-risk-analyst`
- `conservative-risk-analyst`
- `neutral-risk-analyst`

三方必须分别给出 0–10 风险调整评分、建议仓位、最强论点、对交易提案的修改意见、触发器和反证。不得只重复上游报告。

## 6. Phase 5：风险主管最终裁决

三方风险报告完成后，把完整风险辩论、交易员方案和研究主管计划放入任务，`spawn(label: "risk-manager")`。风险主管必须：

- 逐一评价三方观点的证据质量；
- 明确给出最终 `BUY`、`SELL` 或 `HOLD`；
- 给出最终模型仓位上限、入场/目标/止损；
- 给出信心水平、风险等级、监控指标和退出条件；
- 输出三方风险评分汇总，供报告图表使用。

`spawn` 返回的 ID 仅用于运行时标识，不是后台命令 session。不要调用
`write_stdin` 等待 `[risk-manager-END]`；风险主管结果会自动注入。收到结果后
立即进入首席策略官汇总和报告审校，不得用 1–2 句风险摘要提前结束。

## 7. 首席策略官汇总

进入 `chief-strategist` 后，先建立最终证据矩阵：

| 主张 | 支持事实 | 计算/方法 | 反方证据 | 日期与口径 | 置信度 | 报告处理 |
|---|---|---|---|---|---|---|

抽检至少：

- 一个价格/技术指标；
- 一个财务或估值数字；
- 一个公告、政策或新闻事实；
- 一个资金/机构数据；
- 一个目标价或收益风险比计算。

最终判断以风险主管裁决为主，但首席策略官必须纠正任何明显计算错误、时间穿越或无来源结论。

## 8. 可视化与报告

对已核验数据优先生成：

1. 近 60 个交易日收盘价趋势图；
2. 四维评分对比图；
3. 多头与空头论点权重图；
4. 激进/保守/中性风险评分图；
5. 情景目标价或交易价格阶梯图。

使用 `create_research_chart` 写入 `reports/assets/`。没有可靠数列时用表格并说明缺口，不得为了出图编造数据。用 Mermaid 展示“4 路研究 → 多空辩论 → 交易提案 → 3 路风险辩论 → 最终裁决”流程。

最终 Markdown 至少包含：

1. 标题、标的、数据截止日、研究范围与方法；
2. 决策卡片：方向、信心、风险等级、仓位上限、入场、目标、止损；
3. 执行摘要；
4. 四维评分和关键指标；
5. 技术、基本面、新闻与情绪证据；
6. 多空交锋与研究主管裁决；
7. 交易员提案；
8. 三方风险辩论与风险主管裁决；
9. 监控清单、失效条件和情景表；
10. 来源、数据缺口、研究局限性和非投资建议声明。

写入 `reports/<证券代码或简称>-交易分析-<YYYY-MM-DD>.md`。确认同名 HTML 已生成后，调用：

- `create_docx(source_path: ..., template: "research_report")`
- `create_pdf(source_path: ..., template: "research_report")`

最终只交付实际存在的 HTML、DOCX 和 PDF。
